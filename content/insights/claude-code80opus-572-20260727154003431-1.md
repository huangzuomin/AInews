TL;DR:
> Anthropic 给 Claude Code 搞了波超级瘦身，一口气删了 80% 的系统规则。结果开发小哥一抓包发现，最新的 Opus 5 拿到的提示词反而比上代长了 72%。这哪是减肥，分明是偷偷增肌啊！

### 狂删 80%！Claude Code 的提示词迎来了"毕业级"断舍离
前两天，Anthropic 才刚宣布，给 Claude Code 的新模型（Opus 5、Fable 5 等）删掉了超过 80% 的系统提示词。
这波操作，力度有多大？相当于把一本厚厚的《员工行为手册》直接撕了，换成了一页便签。

过去的提示词，为了防止模型犯错，恨不得把所有翻车点都写成明文规定："默认不要写注释！""除非用户要求，否则不要创建计划！"
久而久之，Claude 还没开始写代码，先得花精力判断几百条规则里到底该听谁的。

于是 Anthropic 索性来了场"大扫除"。
最典型的例子就是代码注释规则。那一长串负面清单，如今被压缩成一句话：
> 编写符合周围代码风格的代码，与其注释密度、命名方式和惯用写法保持一致。
翻译成人话：看看你的同事咋写的，跟着学就行。

官方还给出了几条建议，总结起来就是：
- **别给 Claude 写百科全书了**，它能从代码里看出来的事，不用你在 CLAUDE.md 里重复。
- **把长指令拆成 Skill**，按需加载，别一股脑全塞进去。
- **直接给参考代码**，少写大段文字描述。

用 Anthropic 的话说：**少给 Claude 发一本事无巨细的员工手册，多把工具、环境和任务边界设计清楚。**

### 网友破案：Opus 5 反手涨了 72%？？？
正当大家都为这个"教科书级"的瘦身案例鼓掌时，一位叫 **陈成（@chenchengpro）** 的开发者网友，冒出了一个质朴的问题：
"真删了这么多吗？"

他直接把 Claude Code 的 CLI 劫持了，把不同模型真正收到的系统提示词全抓了出来。
然后，一组相当"抓马"的数据出现了：

- **Opus 4.7：15225 字符**（员工手册时代）
- **Opus 4.8：4467 字符**（狂砍 70%，瘦身成功了！）
- **Opus 5：7694 字符**（比 4.8 足足涨了 72%？？？）

说好的狂删 80% 呢？怎么新大哥 Opus 5 还偷偷给自己加餐了？

### 深入扒一扒：不是反弹，是"成长痛"
细扒之后才发现，Anthropic 没撒谎，是大家的关注点跑偏了。
原来每个版本的 Claude Code 里都藏着两套 Prompt，根据模型版本自动切换。
删掉 80%，指的是从旧版提示词体系（4.7 那种）切换到新版体系（4.8 那种）的整体变化。
而 Opus 5 相比 4.8 涨了 72%，是因为 Anthropic 发现：**这届模型太强了，强到有点"主动"过头了。**

根据 Anthropic 的指南，Opus 5 特别喜欢干这几件事：
- 动不动就汇报进度。
- 生成的代码和文档巨长无比。
- 很喜欢召唤子 Agent 来反复验证。

如果你在处理复杂的编程任务，这简直是神来之笔。但如果你只想让它改几行代码，它非要拉个"项目组"开个研讨会，这 Token 消耗和等待时间，你可真受不了。

所以，Opus 5 多出来的 3755 字符，主要用在了两个新板块：
- **Delivering work（交付工作）：** 明确任务范围、汇报频率和交付标准。
- **Corrections（纠错）：** 禁止模型无休止地自我纠正和反复解释。

### AI 的宿命：旧毛病减了，新毛病会精准长在别处
这下逻辑彻底闭环了。
**删掉 80%，是对弱模型的"保姆式"解脱。涨回 72%，是对强模型的"放飞后"收线。**

模型越能自己干活，人类需要手把手教它的地方越少。
但模型越来越有主见以后，哪些事情可以主动做、做到哪一步该停，还是得提前划条线的。

果然，AI 也逃不过这个规律：旧毛病减下去了，新毛病又会精准长在别处。
这波不是打脸，而是属于 Opus 5 的"成长痛"啊。
