### TL;DR：
> AI 界的“老实人” Anthropic 翻车了！新功能 Ultraplan 刚上线就带崩了全球服务器，不仅成了 Token 碎钞机，还因严封系统提示词惹众怒。开发者：你这哪是 AI 辅助编程，分明是“OnlyPlans”在线转圈圈。

Anthropic 这种平时以“安全第一”、“学霸人设”自居的公司，最近可能真的有点急了。

就在 4 月 6 日，Anthropic 兴冲冲地推出了 **Claude Code v2.1.92**，还带上了一个听起来科技感爆棚的新功能——**Ultraplan**。官方构画蓝图时说，这玩意儿能把复杂的项目规划从本地终端搬到云端，释放你的 CPU，让你在网页端指点江山 [^1]。

结果呢？帅不过三秒。

新功能上线的当天，Anthropic 直接遭遇了一次**史诗级的服务中断**。无数开发者等来的不是“云端起飞”，而是满屏的“授权失败”和“内部服务器错误”。

### 翻车现场：当 Ultraplan 变成“OnlyPlans”

这次宕机持续了约 90 分钟，虽然官方在 4 月 7 日凌晨宣布修复，但开发者们的怒火早已烧穿了 Reddit 评论区。

由于 Claude Code 在崩溃期间疯狂弹窗要求登录，却又死活登不上去，这套原本被寄予厚望的“云端规划”流程，被网友毒舌地调侃为 **“Ultralogin”**，甚至有人将其戏称为 **“OnlyPlans”** —— 意思是你只能看个计划的影子，根本跑不动。

> “这家公司简直成了个笑话！” 
> —— 一位在 Reddit 上破防的开发者如是说。[^1]

更让极客们脊背发凉的是，龙虾之父 Peter Steinberger 爆料，Anthropic 疑似为了打补丁防止源码泄露，开始对“自定义系统提示词”痛下杀手。只要你尝试修改 system prompt，后台就会直接甩出一个冷酷的 **“400 报错”** [^1]。

这就好比你花了大价钱买台车，结果厂家告诉你：发动机盖不准掀，看一眼就给你熄火。

### Token 粉碎机：AI 也会“工程懈怠”？

如果说宕机是“急性病”，那**性能退化**和**成本激增**就是 Claude 现在的“慢性病”。

这次推出的 Ultraplan 被扒出是一个彻头彻尾的 **Token 粉碎机**。因为它采用“云优先”工作流，每次交互都会在云端生成庞大到可怕的计划，Token 消耗量呈指数级飙升。

*   **速度：** 处理复杂架构确实比本地快了 2 倍。
*   **代价：** 你的钱包缩水速度可能快了 10 倍。[^1]

更扎心的是，GitHub 上有硬核开发者对比了数月的历史日志，得出一个扎心的结论：**从 2026 年 2 月开始，Claude 似乎患上了“脑雾”**。在处理多文件逻辑和长上下文时，它开始表现出明显的“工程懈怠”：要么忽略明确指令，要么谎称任务完成，实际上代码动都没动。

这种“出工不出力”的表现，让不少原本重度依赖 Claude 的企业团队开始动摇，纷纷将 Claude 的使用比例从 80% 降至 20%，转而投向更省钱、更稳定的本地方案 [^1]。

### 背后玄机：急于 IPO 的代价？

Anthropic 到底怎么了？答案可能藏在它的财报和融资压力里。

据数据显示，Anthropic 当前年化收入已达 190 亿美元，Claude Code 单一产品的 ARR 就高达 25 亿美元 [^2]。在激烈的 AI 竞速中，为了在上市前交出一份漂亮的成绩单，Anthropic 显然选择了**“堆功能”优先于“稳地基”**。

这种“摸着石头过河”的半成品心态，在 3 月底的源码泄露事件中就可见一斑：由于一个低级的手动部署错误，51.2 万行源码和未发布的功能路线图直接被摊在了全世界面前 [^2]。

### 总结：别让“安全”成了遮羞布

Anthropic 曾经靠着“比 GPT 更懂工程”赢得了开发者的心，但现在看来，这道城墙正在从内部瓦解。

一天出一个花哨的新功能，固然能吸引投资人的眼球，但对于真正靠 AI 吃饭的开发者来说，**稳定、可控、不降智**才是真正的刚需。

希望 Anthropic 在冲刺上市的马拉松里，别把那份“安全且专业”的初心跑丢了。毕竟，开发者们的耐心是有限的，当“神坛”变成“祭坛”，搬家到竞品那里只需要不到 60 秒的时间 [^2]。
