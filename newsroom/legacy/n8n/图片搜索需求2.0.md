### **1. 概述 (Overview)**

#### **1.1 项目目的**
本项目旨在创建一个独立的、可复用的n8n子工作流。其核心功能是根据输入的主题关键词和文章标题，**通过多模态AI分析，从一系列高质量候选图片中，智能选择出在上下文、美学和专业性上最匹配的一张**。此工作流旨在实现真正意义上的自动化、高质量内容配图，模拟人类高级图片编辑的决策过程。

#### **1.2 项目范围**
本工作流的范围**包括**：
* 接收外部传入的关键词**和文章标题/摘要**。
* 调用第三方图片服务API获取候选图片。
* **调用多模态AI模型API，提交候选图片和上下文进行分析。**
* **解析AI的决策结果，并根据结果选定最终图片。**
* 处理API调用和AI响应解析过程中的异常。
* 返回一个结构化的JSON对象，包含最终选定的图片信息。

### **2. 功能需求 (Functional Requirements)**

#### **FR-01: 上下文信息接收**
工作流必须能够在其入口点接收以下信息：
* **FR-01.1:** 一个包含一个或多个关键词的字符串。
* **FR-01.2:** 一个代表文章核心思想的标题或摘要字符串。

#### **FR-02: 候选图片获取**
* **FR-02.1:** 工作流必须使用 **Pexels API (v1)** 作为其图片来源。
* **FR-02.2:** 必须调用Pexels的 `GET /v1/search` API端点。
* **FR-02.3:** API请求必须包含以下查询参数：
    * `query`: 值来自于 **FR-01.1** 中接收的关键词。
    * `per_page`: 值应设为`8`，以获取一个数量适中、质量较高的候选图片池。
    * `orientation`: 值必须硬编码为 `landscape`。
* **FR-02.4:** (保持不变) API请求必须通过 `Authorization` HTTP头进行身份验证。

#### **FR-03: 候选图片预处理**
在提交给AI分析前，必须对 **FR-02** 获取的图片列表进行预处理：
* **FR-03.1:** 过滤掉所有 `width` 属性小于 `1200px` 的图片。
* **FR-03.2:** 提取所有通过筛选的图片的URL，构建一个候选URL列表。
* **FR-03.3:** 若预处理后无任何候选图片，则必须触发 **EH-02** 错误处理流程。

#### **FR-04: 多模态AI集成与甄选**
* **FR-04.1:** 工作流必须集成并调用一个支持视觉分析的多模态AI模型（如 **Google Gemini Pro Vision**）。
* **FR-04.2 (Prompt工程):** 必须构建一个精确的、面向AI的Prompt。该Prompt必须包含：
    * **角色设定**: "你是一位专业的资深图片编辑。"
    * **任务描述**: "你的任务是为下面的文章标题，从提供的候选图片列表中，选择一张最合适的配图。"
    * **评估标准**: "请基于以下三个维度进行评估：1. **主题相关性** (图片内容是否紧扣文章主题)；2. **视觉吸引力** (图片构图、色彩和美感)；3. **专业性** (图片是否看起来像专业摄影作品，而非随手拍或截图)。"
    * **上下文输入**: 清晰地提供“文章标题” (**FR-01.2**)。
    * **候选图片输入**: 清晰地提供“候选图片URL列表” (**FR-03.2**)。
    * **输出格式要求**: "请不要进行任何解释。仅返回一个符合以下格式的JSON对象，其中`bestImageIndex`是你选择的图片在列表中的索引（从0开始），`reasoning`是你选择的简短理由：`{\"bestImageIndex\": <number>, \"reasoning\": \"<string>\"}`"
* **FR-04.3 (AI响应解析):** 工作流必须能够解析AI返回的JSON字符串，并成功提取 `bestImageIndex` 的值。

#### **FR-05: 最终选择与备用逻辑**
* **FR-05.1 (首选逻辑):** 使用 **FR-04.3** 中获取的索引，从 **FR-03.2** 的候选列表中定位并选择最终的图片。
* **FR-05.2 (备用逻辑/Fallback):** **在任何情况下**（包括AI API调用失败、超时、返回非JSON格式、或解析JSON失败），如果备选逻辑被触发，工作流**必须**自动选择候选列表中的第一张图片作为最终结果，以确保流程的健壮性。

#### **FR-06: 输出格式化**
(保持不变) 工作流的最终输出必须是 **3.2.1** 或 **3.2.2** 中定义的结构化JSON对象。

### **3. 接口规范 (Interface Specifications)**

#### **3.1 输入接口 (已更新)**
工作流必须能处理以下格式的JSON输入：
```json
{
  "body": {
    "keywords": "string",
    "articleTitle": "string"
  }
}
```
* `keywords`: 用于图片搜索的关键词字符串。
* `articleTitle`: 用于AI进行上下文分析的文章标题或摘要。

### **4. 错误处理与边缘情况 (Error Handling & Edge Cases)**

#### **EH-01, EH-02, EH-03:** (保持不变) 处理Pexels API的各类错误。

#### **EH-04: 多模态AI API错误 (新增)**
如果Gemini API调用失败（如认证、计费、速率限制、服务不可用等），工作流不能崩溃，必须触发 **FR-05.2** 的备用逻辑。

#### **EH-05: AI响应解析失败 (新增)**
如果AI返回的响应不是一个有效的JSON字符串，或者JSON中缺少`bestImageIndex`字段，工作流不能崩溃，必须捕获此异常并触发 **FR-05.2** 的备用逻辑。
