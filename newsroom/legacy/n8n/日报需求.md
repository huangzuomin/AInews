

## **AI内参-自动化AI日报生成工作流软件需求说明文档 (SRD)**

**版本: 1.1**
**日期: 2025年6月22日**

### **1. 概述**

#### **1.1 项目背景**

“AI内参”网站每日收录大量AI领域的资讯文章。为了提高内容生产效率，快速为读者提供每日精华内容，我们计划开发一个自动化的工作流。该工作流将自动抓取、分析、筛选并整合每日最重要的AI资讯，最终生成一篇结构化的“AI日报”综述文章。

#### **1.2 项目目标**

  * **自动化内容处理**: 替代手动筛选和总结文章的繁琐工作，实现内容生产的自动化。
  * **提升内容质量**: 通过数据驱动的评分模型，确保筛选出的文章具有高质量和高价值。
  * **稳定高效产出**: 每日定时生成一篇格式统一、内容精炼的AI日报，保证内容更新的稳定性和时效性。
  * **技术实现**: 本项目旨在通过无代码/低代码平台 **n8n** 实现，利用其节点化的工作流编排能力，对接数据库和大型语言模型（LLM）API。

#### **1.3 目标用户**

  * “AI内参”网站的内容编辑和运营人员。

#### **1.4 名词解释**

  * **SRD**: Software Requirements Document，软件需求说明文档。
  * **n8n**: 一个开源的、可视化的工作流自动化工具。
  * **工作流 (Workflow)**: 指在n8n中创建的一系列自动化步骤（节点）的集合。
  * **数据库 (Database)**: 存储`ai_articles`表的关系型数据库（根据截图推断为PostgreSQL）。
  * **LLM**: Large Language Model，大型语言模型，如GPT系列、Gemini、Claude等，用于内容分析和生成。
  * **综述文章 (Review Article)**: 指最终由工作流生成的、汇总了多篇精华文章的日报。

### **2. 功能需求 (Functional Requirements)**

#### **FR-01: 工作流定时触发**

  * **2.1.1** 工作流需要有一个定时触发器。
  * **2.1.2** 触发器应设置为**每日晚上20:05**自动启动。

#### **FR-02: 数据提取 (Fetch Articles)**

  * **2.2.1** 工作流需要连接到存储`ai_articles`表的数据库。
  * **2.2.2** 从`ai_articles`表中查询并提取指定时间窗口内的所有文章。
  * **2.2.3** **时间窗口**: 从**前一天的晚上20:00:00**到**当天的晚上20:00:00**。
  * **2.2.4** **查询逻辑**: 使用SQL语句进行查询。查询条件应基于`published_at`或`created_at`字段。
  * **2.2.5** **提取字段**: 必须至少提取 `id`, `title`, `content`, `source_url`, `author`, `published_at`, 以及 **`word_count`** 字段用于后续处理。
  * **2.2.6** **查询示例 (SQL for PostgreSQL)**:
    ```sql
    SELECT
        id,
        title,
        content,
        source_url,
        author,
        published_at,
        word_count
    FROM
        ai_articles
    WHERE
        COALESCE(published_at, created_at) >= NOW() - INTERVAL '1 day'
        AND COALESCE(published_at, created_at) < NOW();
    ```

#### **FR-03: 文章评分 (Score Articles)**

  * **2.3.1** 工作流需要遍历上一步提取出的每一篇文章。
  * **2.3.2** 对每一篇文章，调用LLM API，**仅根据其 `content` 字段** 进行多维度评分。
  * **2.3.3** **评分维度与标准**: LLM需要评估并返回一个包含以下\*\*浮点数（支持小数点后一位）\*\*分数的JSON对象：
      * `novelty_score` (创新性/新颖性, 1.0-10.0分)
      * `impact_score` (影响力, 1.0-10.0分)
      * `clarity_score` (清晰度/可读性, 1.0-10.0分)
      * `depth_score` (深度, 1.0-10.0分)
  * **2.3.4** **LLM Prompt 示例**:
    ```
    你是一位资深的AI行业分析师。请仔细阅读并分析以下这篇完整的AI文章内容，并根据以下维度对其进行评分。请返回1.0到10.0之间的浮点数分数，以提高评分的精确度。

    评分维度:
    1.  novelty_score: 创新性，是否包含突破性技术或新颖观点。
    2.  impact_score: 影响力，主题对行业的潜在影响。
    3.  clarity_score: 清晰度，文章结构和论述的清晰程度。
    4.  depth_score: 深度，内容是否提供了深入的分析。

    文章内容:
    """
    {{ $json.content }}
    """

    请严格按照以下JSON格式返回你的评分结果:
    {
      "novelty_score": 8.5,
      "impact_score": 9.2,
      "clarity_score": 7.8,
      "depth_score": 8.9
    }
    ```
  * **2.3.5** **计算最终得分 (`ai_score`)**:
    1.  **计算加权分**: `weighted_score = (novelty_score * 0.3) + (impact_score * 0.4) + (clarity_score * 0.1) + (depth_score * 0.2)`
    2.  **应用平局决胜值 (Tie-breaker)**: 为减少得分碰撞概率，将文章词数作为微小影响因子加入分数：`tie_breaker_value = word_count * 0.00001`
    3.  **计算最终得分**: 将加权分与平局决胜值相加，并四舍五入到**小数点后两位**。
        `ai_score = ROUND( (weighted_score + tie_breaker_value), 2 )`
  * **2.3.6** **数据合并**: 将计算出的 `ai_score` 与原始文章数据（包括`id`）合并，用于下一步的数据库更新。

#### **FR-04: 更新文章评分到数据库 (Update Scores to DB)**

  * **2.4.1** 遍历所有已计算出`ai_score`的文章。
  * **2.4.2** 对每一篇文章，执行一个数据库`UPDATE`操作，将其`ai_score`字段的值更新为计算出的新分数。
  * **2.4.3** **更新逻辑**: `UPDATE ai_articles SET ai_score = [计算出的ai_score] WHERE id = [对应的文章id];`
  * **2.4.4** **更新示例 (n8n SQL)**:
    ```sql
    -- This would be in a loop for each item in n8n
    UPDATE ai_articles
    SET ai_score = {{ $json.ai_score }}
    WHERE id = {{ $json.id }};
    ```

#### **FR-05: 文章筛选 (Select Top Articles)**

  * **2.5.1** 将所有评分后的文章根据 **`ai_score`** 字段进行**降序排序**。
  * **2.5.2** 选取排序后的**前5篇**文章作为当日日报的核心素材。

#### **FR-06: 生成综述文章 (Generate Review Article)**

  * **2.6.1** 将上一步筛选出的Top 5文章的`title`, `content`, `source_url`, 和 `author` 作为输入，再次调用LLM API。
  * **2.6.2** **生成要求**: 指示LLM生成一篇结构化、语言流畅的综述文章。文章应包含以下部分，并以Markdown格式输出：
    1.  **日报大标题**: 例如 "AI内参日报 | {当天日期}: {当天最重要新闻的简短概括}"。
    2.  **开篇导语 (Introduction)**: 约100-150字，概述今天AI领域最重要的动态和趋势。
    3.  **文章摘要列表 (Article Summaries)**: 遍历Top 5文章，为每一篇生成一个独立的摘要模块。每个模块包含：
          * **文章标题**: 使用`###` (Markdown H3) 标签。
          * **核心看点 (Key Takeaway)**: 2-3句最核心的观点提炼。
          * **内容摘要 (Summary)**: 约200字的详细摘要。
          * **原文信息 (Source Info)**: "原文作者: {author}, 来源: [{source\_url}](https://www.google.com/search?q=%7Bsource_url%7D)"
    4.  **结尾总结 (Conclusion)**: 约100字，对今天的资讯进行简短收尾。
  * **2.6.3** **LLM Prompt 示例**:
    ```
    你是一位顶级的科技媒体主编，你的任务是将今天最重要的5篇AI文章整合成一篇高质量的“AI日报”。请严格按照指定的Markdown格式输出。

    今天是 {{ $now.format('YYYY年MM月DD日') }}。

    以下是5篇精选文章的核心信息：
    ---
    文章1:
    标题: {{ $json.top_articles[0].title }}
    内容: {{ $json.top_articles[0].content }}
    作者: {{ $json.top_articles[0].author }}
    来源URL: {{ $json.top_articles[0].source_url }}
    ---
    文章2:
    ... (以此类推)
    ---

    请生成日报，包含以下部分：
    1.  一个吸引人的日报大标题。
    2.  一段开篇导语。
    3.  为每篇文章生成一个包含“### 标题”、“核心看点”、“内容摘要”和“原文信息”的摘要模块。
    4.  一段结尾总结。

    请确保语言专业、流畅、精炼。直接输出Markdown格式的全文。
    ```
  * **2.6.4** **输出**: 工作流此步骤的输出应为一段完整的Markdown格式文本。

#### **FR-07: 结果存储 (Store the Result)**

  * **2.7.1** 将上一步生成的Markdown综述文章存回数据库`ai_articles`表中，作为一篇新的文章。
  * **2.7.2** **字段映射**:
      * `title`: 设为综述文章的大标题。
      * `content`: 设为综述文章的Markdown全文。
      * `status`: 设为 'draft' (草稿) 或 'review\_generated'。
      * `summary`: 设为综述文章的开篇导语。
      * `is_selected`: 可设为 `true`。
      * `ai_score`: **此字段应留空 (NULL)**，因为它是一篇综述文章，本身不参与评分。
      * 其他相关字段（如`created_at`, `updated_at`）使用数据库默认值。

### **3. 非功能需求 (Non-Functional Requirements)**

#### **NFR-01: 可靠性 (Reliability)**

  * **3.1.1** **错误处理**: 工作流中的每一步（特别是API调用和数据库操作）都应有错误处理机制。
  * **3.1.2** **重试机制**: 对LLM API的调用应设置重试机制（例如，最多重试3次，间隔10秒），以应对临时的网络或服务抖动。
  * **3.1.3** **失败通知**: 如果工作流执行失败，应通过邮件或即时消息向管理员发送失败告警，并附上错误日志。

#### **NFR-02: 性能 (Performance)**

  * **3.2.1** 整个工作流的端到端执行时间应控制在**30分钟**以内。
  * **3.2.2** 对LLM的调用应进行优化，例如在评分阶段可以考虑并行处理多篇文章。

#### **NFR-03: 可配置性 (Configurability)**

  * **3.3.1** 以下关键参数应在n8n工作流中设置为易于修改的变量，而无需修改核心逻辑：
      * 数据库连接凭证。
      * LLM API Key和模型名称。
      * 筛选时间窗口（例如，`20:00`这个时间点）。
      * Top N文章的数量（当前为5）。
      * 评分模型中的权重系数。
      * 所有提供给LLM的Prompt模板。

### **4. 技术栈与环境假设**

  * **工作流引擎**: n8n Cloud 或自托管的n8n实例。
  * **数据库**: 可通过n8n节点访问的PostgreSQL数据库。
  * **AI模型服务**: 能够通过REST API访问的LLM服务，并已获取有效的API Key。
  * **环境**: n8n运行环境可以访问公网（调用LLM API）和内部数据库。
