### **1. 概述 (Overview)**

#### **1.1 项目目的**
本项目旨在创建一个独立的、可复用的n8n子工作流，其核心功能是根据输入的一组主题关键词，自动从高质量图库中搜索、筛选并返回一张最合适的图片URL。此工作流旨在解决自动化内容生产中，手动配图耗时且图片质量参差不齐的痛点。

#### **1.2 项目范围**
本工作流的范围**包括**：
* 接收外部传入的关键词。
* 与第三方图片服务API进行交互。
* 根据预设规则对图片进行筛选。
* 处理异常情况（如未找到图片）。
* 返回一个结构化的JSON对象，包含最终选定的图片信息。

本工作流的范围**不包括**：
* 生成输入所用的关键词。
* 调用本工作流的主流程逻辑。
* 将最终图片嵌入或上传到任何CMS或最终媒介。

#### **1.3 目标用户**
本工作流的直接用户是其他n8n工作流，特别是需要自动化配图的内容创建工作流（例如，博客文章自动发布、社交媒体帖子生成等）。

### **2. 功能需求 (Functional Requirements)**

#### **FR-01: 关键词接收**
工作流必须能够在其入口点（Start Node）接收一个包含一个或多个关键词的字符串。

#### **FR-02: 第三方图库API集成**
* **FR-02.1:** 工作流必须使用 **Pexels API (v1)** 作为其唯一的图片来源。
* **FR-02.2:** 必须调用Pexels的 `GET /v1/search` API端点。
* **FR-02.3:** API请求必须包含以下查询参数：
    * `query`: 值来自于 **FR-01** 中接收的关键词。
    * `per_page`: 值应设为`15`，以获取足够的候选图片池。
    * `orientation`: 值必须硬编码为 `landscape`（横向），以满足通用文章配图需求。
* **FR-02.4:** API请求必须通过 `Authorization` HTTP头进行身份验证，其值来自于n8n中预先配置好的凭证。

#### **FR-03: 图片筛选逻辑**
工作流必须对API返回的图片列表执行以下筛选：
* **FR-03.1 (分辨率筛选):** 丢弃所有 `width` 属性小于 `1200px` 的图片。此最小宽度值应在代码中作为可配置变量存在，以便未来调整。
* **FR-03.2 (数据完整性筛选):** 丢弃任何缺少 `src.original` 属性的图片记录。

#### **FR-04: 图片选择逻辑**
* **FR-04.1 (首选逻辑):** 从通过 **FR-03** 筛选的图片列表中，选择第一张图片作为最终结果。
* **FR-04.2 (备选逻辑/Fallback):** 如果没有任何图片通过 **FR-03** 的筛选（但API返回了结果），则必须从原始返回的图片列表中选择第一张图片。此举确保在极端情况下依然能返回一张图片，避免工作流中断。

#### **FR-05: 输出格式化**
工作流的最终输出必须是一个独立的、结构化的JSON对象，且仅包含以下字段：
* `imageUrl` (string): 最终选定图片的最高质量URL (来自Pexels返回的`src.original`字段)。
* `altText` (string): 图片的描述文字 (来自Pexels返回的`alt`字段)，用于SEO和可访问性。
* `photographer` (string): 摄影师的姓名 (来自Pexels返回的`photographer`字段)。
* `photographerUrl` (string): 指向摄影师Pexels主页的链接 (来自Pexels返回的`photographer_url`字段)。
* `error` (string/null): 正常情况下为`null`，在发生错误时（见**4.2**）为错误描述字符串。

### **3. 接口规范 (Interface Specifications)**

#### **3.1 输入接口**
工作流必须能处理以下格式的JSON输入：
```json
{
  "body": {
    "keywords": "string" 
  }
}
```
* `keywords`: 一个逗号分隔或空格分隔的字符串，包含用于搜索的关键词。

#### **3.2 输出接口**
* **3.2.1 成功输出:**
    ```json
    {
      "imageUrl": "https://images.pexels.com/photos/...",
      "altText": "A descriptive text about the image.",
      "photographer": "John Doe",
      "photographerUrl": "https://www.pexels.com/@john-doe",
      "error": null
    }
    ```
* **3.2.2 失败输出 (例如，未找到图片):**
    ```json
    {
      "imageUrl": null, // 或一个预设的默认占位图URL
      "altText": null,
      "photographer": null,
      "photographerUrl": null,
      "error": "No images found for the given keywords."
    }
    ```

### **4. 错误处理与边缘情况 (Error Handling & Edge Cases)**

#### **EH-01: API认证失败**
如果Pexels API因身份验证问题返回401 Unauthorized错误，工作流应停止执行，并在HTTP Request节点上明确显示该错误。

#### **EH-02: API未返回任何图片**
如果Pexels API返回200 OK但 `photos` 数组为空，工作流不能崩溃。必须按照 **3.2.2** 的格式返回一个失败输出。

#### **EH-03: API服务不可用**
如果Pexels API返回5xx系列服务器错误，工作流应停止执行，并在HTTP Request节点上记录该错误。

---

### **5. 非功能性需求 (Non-Functional Requirements)**

#### **NFR-01: 性能 (Performance)**
工作流从接收请求到返回结果的总执行时间，应主要取决于Pexels API的响应速度。目标是在API正常响应的情况下，自身处理时间不超过500毫秒。

#### **NFR-02: 可配置性 (Configurability)**
代码实现中，应将关键参数（如最小宽度`minWidth`，每页结果数`per_page`）定义为文件顶部的常量或变量，以方便未来快速调整而无需重构代码逻辑。

#### **NFR-03: 可靠性 (Reliability)**
工作流必须是健壮的，能够处理**章节4**中定义的所有错误情况，确保不会因为可预见的输入或API问题而导致意外崩溃。
