- 日期：2026-09-11
- 配套：`DESIGN-automation-2026-09-11.md`（本文件是该设计中 L1.5 选题与 L2 生成的详细规范）
- 依据：`D:\Work\n8n\` 原始 n8n 工作流存档（21 个 JSON + 3 份需求文档）逐条提取；存量文章 400 篇抽样实测
- 一句话：**原始设计的意图是"先过分类闸，再用公式算分，再按配额分配"，写作侧是"深度解释型科技报道 + 结构随内容变形"。现状把这两件事都压缩成了几行 SOP，所以"哪些值得写"和"写成什么样"都变成了会话现场发挥。**

## 0. 考古结论：原始意图有三代演进，且比现状精细得多

### 0.1 选题（Selection）

| 代 | 文件 | 机制 |
|---|---|---|
| Gen 1 | `Daily_AI_News_Summary_Workflow.json` / `Weekly_..._Newsletter2.json` | 五维打分（重要性/技术创新/行业影响/时效热度/读者价值）→ 取 Top 5 |
| Gen 2 | `日报需求.md`（SRD v1.1）+ `AI_Daily_Report_Workflow.json` | **四维加权公式**：`weighted = novelty*0.3 + impact*0.4 + clarity*0.1 + depth*0.2`，加 `word_count*0.00001` 防同分碰撞，四舍五入两位 |
| Gen 3 | `Daily_AI_Summaries.json` / `Optimized_..._Workflow.json` | 五维 × 10 分求和（满分 50），维度含**「对目标读者的价值和可读性」** |

三代之外，还有一个**贯穿始终的分类闸**（`Is AI Related` / `Is AI Related2..7`，出现在 `AI____.json`、`My_workflow.json`），它才是编辑身份的真正定义：

```
判断它是否与人工智能相关，并且是偏向中国读者感兴趣的 AI 领域的专业资讯。
### 判断标准：
是否直接与人工智能技术、算法、应用、研究进展、行业趋势、公司动态等相关。
是否涉及人工智能在特定专业领域（如医疗、金融、教育、工业等）的应用或影响。
内容是否具有一定的深度或专业性，而不仅仅是泛泛的社会议题。
如果涉及中国相关内容，是否是关于中国的 AI 发展、政策、企业或研究成果。
排除与人工智能相关但更多是社会、娱乐、政治、八卦等非专业性或泛话题性的内容。
排除与人工智能相关但明显是美国或欧洲读者更感兴趣的政治、社会争议等内容，
除非其对全球 AI 发展或中国有直接影响。
```

并带硬时效窗：早期 12h、后期收紧到 **4h**、编排层再收到 **0.5h**（`If - Within 0.5 Hours`）。

> **这是本次考古最重要的一条。** 原始设计里"什么算 AI 内参的内容"是一份**可评审的、显式的判断标准**；今天是 `RUNBOOK` 里的一句"选题优先级：ai-models > industry/paper > ai-products > tip"——它按**分类**排序，不按**价值**排序，而且把判断整体外包给了 aihot 的 `score`（一个不透明、不可调、不可审的外部函数）。

### 0.2 生成（Style）

| 代 | 位置 | 规范 |
|---|---|---|
| Gen 1 | `Write Article3/4/5`（`AI____.json`、`My_workflow.json`） | "你是一名人工智能助手…"：TL;DR + 引言 + 结论；**Wikipedia 式脚注**（`[^1]`，文末 `## References`，要求编号连续不跳号）；中立新闻报道基调、第三人称；`<article>` 包裹 |
| Gen 2 | `Write Article` / `Write Article8` | **角色升格为「专业科技记者」+ 明确风格参照（MIT Technology Review 记者 Karen Hao 式）**；深度分析叙事；技术原理 + 社会影响；可读性明确写入要求 |
| 日报 | `Generate Summary Article` / `Basic LLM Chain1` | "顶级科技媒体主编"：大标题格式 `AI内参日报 \| yyyy年MM月dd日: <概括>`；导语 100–150 字；每篇模块 = `### 标题` + 核心看点（2–3 句）+ 内容摘要（约 200 字）+ 原文信息；结尾总结约 100 字；全文 1500–2000 字 |

Gen 2 里最有价值、也最被低估的是**「结构五型 + 决策指南」**——它把"文章该长什么形状"变成了一个可复用的判断树：

```
A. 突发新闻型：开门见山陈述核心事实 → 按重要性递减展开 → 自然段落，无需小标题
B. 深度分析型：2-3 个核心小标题 → 技术原理解析 / 行业影响分析 / 未来发展趋势
C. 人物/公司聚焦型：故事化叙述 → 按时间线或逻辑自然展开 → 避免生硬小标题
D. 对比分析型：对比性小标题 → A方案 vs B方案 / 优势与挑战
E. 教程/解释型：按逻辑层次递进 → 问题式小标题（这项技术如何工作？它解决了什么问题？）

结构决策指南：
内容简单直接 → 自然段落，无小标题      内容复杂多层 → 最多 3 个小标题
信息密集 → 适当使用列表和引用块        故事性强 → 按叙述逻辑自然展开
技术性强 → 按理解难度递进组织

段落组织原则：每段聚焦一个核心观点 / 段落间用过渡句 / 关键数据和引语独立成段
必备要素：TL;DR 用引文格式（> 开头），2-3 句中文概括核心
```

### 0.3 为什么被放弃的是它，而病灶却在别处

`HANDOVER §4.4` 否决 n8n 的理由是"功能/提示词/正则封在节点 JSON：不可 diff、不可测试、不可回滚；本次所有生产事故都源于此形态"。**这个诊断对了一半。**

| 原始 n8n 的失败 | 真实病灶 | 与"封在 JSON 里"有关吗 |
|---|---|---|
| 37 天停更 | 单一 LLM 供应商断供 + **零告警** | **无关**。告警是运维缺失，与提示词放哪无关 |
| 额度烧穿 | **成本倒挂**：每条 RSS 都生成全文 + 逐篇评分 + 逐篇 Tavily + 逐条 Google 搜图，而日报只引用 5 篇 | **无关**。这是漏斗方向错，不是封装形态 |
| 4968 条垃圾 commit | Execute Command 未开表达式求值 | **无关** |
| 3 个工作流并发写同一工作树 | 缺单一写入者 | **无关** |
| 同事件多源重复成文 | 只有 guid 判重，无语义去重 | **无关** |

**结论：被封在 JSON 里造成的是"不可维护"，但造成停更和烧钱的是另外四件事。** 把提示词搬到文件里解决的是维护性；上面四条要靠告警、漏斗、单一写入者、状态化去重来解决——这正是我在自动化设计里把 L0/L1/L4 放在 L2 之前的原因。

**因此本规范的正确姿态是：继承原始设计的选题方法论与风格方法论，丢弃它的封装形态与成本结构。**

## 2. 选题规范：四段式（S0 → S3）

设计原则：**只有 S1/S2 用 LLM，且都批量；S0/S3 是纯规则；最终排序公式在代码里，不在提示词里。** 这直接修正现状的两个病：把判断外包给外部 `score`、以及原始系统的成本倒挂。

### S0 硬规则预筛（零成本，纯确定性）

| 规则 | 参数 | 理由 |
|---|---|---|
| 时效窗 | 快讯 24h / 洞察 72h / 常青不限 | 与班次对齐；原文 4h 太窄，会把有用内容挡在门外 |
| 来源域名 | 白名单优先（官方 blog / release notes / 论文 / 权威媒体），其余降权入池 | 合规红线落地为代码 |
| 指纹去重 | URL 规范化 hash + 标题 3-gram | 取代 grep 9,376 文件 |
| 语言 | 中/英；其他语言仅当有英文源时入池 | 避免机翻二次失真 |
| 最小信息量 | 标题 ≥ 8 字 且 有 `links.original` | 无原文链接 = 无法核事实 = 不写 |
| 垃圾特征 | 标题全部大写 / 含 "🔥" 等表情 / 纯列表页 | 低成本掐掉噪音 |

### S1 分类闸（便宜模型，批量 20 条/次）—— 继承原始设计，现代化改写

输出布尔 + 一句理由。判定标准 = 原始 7 条，但补两条今天的现实约束：

- 原 7 条 include/exclude 全保留（见 §4.1 提示词）
- **新增排除**：产品促销 / 招聘 / 融资快讯中无技术或行业实质的条目
- **新增要求**：必须能指出「这条对中文读者有什么用」——写不出就不通过

### S2 多维打分（便宜模型，批量，仅对 S1 通过者）—— 公式回到代码

| 维度 | 权重 | 打分依据（给 LLM 的定义） |
|---|---|---|
| `novelty` 新颖性 | 0.25 | 是否含突破性技术、新数据、新观点；还是复述已知 |
| `impact` 影响力 | 0.35 | 对行业的实际影响面（开发者/企业/监管/普通用户） |
| `evidence` 证据充分度 | **0.20（新增）** | 原文是否可及、是否有可核的数字与一手表述 |
| `readability` 可读性 | 0.10 | 原文的信息组织是否足以支撑一篇易懂的改写 |
| `freshness` 时效性 | 0.10 | 相对当前时间的衰减 |

```
weighted      = Σ(score_i × weight_i)
tie_breaker   = word_count × 0.00001        # 继承原始设计，防同分碰撞
final_score   = round(weighted + tie_breaker, 2)
```

三条硬约束（都是对原始设计的修正）：

1. **权重放在 `scoring.yaml`，不写在提示词里。** LLM 只产子分与理由；排序、阈值、配额全部在代码。这样调权重不需要改提示词、不需要重跑 LLM。
2. **`evidence` 权重 0.20 是新增维度的关键。** 原始设计没有"能不能核到事实"这一维，这正是后来 9,369 篇里大量内容只能靠 aihot 摘要成文的结构性原因（`HANDOVER §7-P3` 自己承认"未逐篇打开原文"）。
3. **`clarity` 从原设计的"评估原文清晰度"改为 `readability`"是否支撑改写"**——我们不需要原文写得漂亮，只需要它信息足够。

### S3 配额与分流（确定性）

| 出口 | 选什么 | 数量 | 发布闸 |
|---|---|---|---|
| 早报（`morningnews/`） | 当日 `final_score` Top N，聚合成列表 | 8–10 条 | T0 自动 |
| 日报（`newspaper/`） | 当日 Top 5，写成综述 | 1 期 | T0 自动 |
| 洞察 T1（`insights/`） | `final_score ≥ θ1` **且** 属"一手源改写"（官方发布/论文摘要） | ≤3 篇/天 | CI 自动 + 事后抽检 |
| 洞察 T2 | `final_score ≥ θ2` **且** 含数字/观点/争议判断 | ≤2 篇/天 | **PR 待审** |
| 落选 | 其余全部 | — | 写 `state/decisions.jsonl`（分数 + 卡在哪一段） |

阈值 θ1/θ2 初始建议 θ1=6.5 / θ2=7.5（按上面权重满分为 10），**上线两周后用 GA4 数据标定**。

**为什么必须有配额而不是"越多越好"**：原始系统 23 篇/天 × 9,369 篇换来的 28 天收益是 $0.36——产量从来不是约束（见 review §3）。

### S4 闭环：让"核心指标"真的可观测

```
打分 → 发布 → GA4 landing page 会话数（按 prompt_version / 选题维度分组）→ 每 2 周重标定权重
```

没有这一步，权重就是审美；有了这一步，"哪些选题值得生产"才是可验证的命题。**这也是现状唯一完全没有的东西。**

## 3. 风格与可读性规范

### 3.1 角色定调（对原始设计的一处修正）

原始 Gen 2 写的是"模仿 MIT Technology Review 资深记者 Karen Hao 的写作风格"。**建议改掉，理由有三：**

1. **人格权/职业伦理**：以在世记者的名义风格量产内容，是明确的风险点（你自己在新闻机构工作，这条更敏感）。
2. **与合规定位冲突**：我在自动化设计里主张 T0/T1 层的抗辩基础是"带署名的聚合与改写"。声称"模仿某人"会把抗辩基础变成"风格挪用"。
3. **方法论上也不必要**：真正有用的是**风格特征**，不是**某个人的名字**。

改写为特征描述（保留原始能力，去掉风险）：

```
深度解释型科技报道：先讲清技术原理，再论行业与社会影响；
语言准确但对非专家可读；中立、不吹不黑，但要有前瞻判断；
每段聚焦一个观点，关键数据与引语独立成段。
```

### 3.2 结构随内容变形（继承原始五型）

保留 §0.2 的 A–E 五型与决策指南。**这是本次考古里最有价值、最不该丢的资产**：它让"文章长什么形状"由内容决定，而不是让所有文章套同一个模板。

对照现状：现在全部洞察都是固定模板（TL;DR → 2-3 个 ### → `### 展望` → `## 引用`）——**所以 9,376 篇在结构上彼此雷同**，这正是搜索引擎判定"规模化生成"最直接的信号之一。

| 类型 | 触发条件 | 形状 |
|---|---|---|
| A 突发 | 重大发布、突发事件 | 无小标题，重要性递减 |
| B 深度 | 技术解析、趋势 | ≤3 个小标题：原理 / 影响 / 趋势 |
| C 人物公司 | 企业动态、人物 | 故事化，按时间线，无生硬小标题 |
| D 对比 | 竞品、政策 | 对比性小标题或直接段落对比 |
| E 教程 | 技术科普、概念 | 问题式小标题，按理解难度递进 |

### 3.3 可读性的三层约束

这是"可读性如何设置"的正面回答：**风格不能全自动，但可读性的一大半可以。** 所以拆成三层，各司其职。

| 层 | 谁执行 | 内容 | 可否阻断发布 |
|---|---|---|---|
| **L-a 生成指令** | LLM（写作时） | 角色定调 + 五型结构 + 段落原则 + 脚注规范 | 否 |
| **L-b 机器门禁** | CI 脚本（入库前） | 下表全部指标 | **是**（不达标即拒收） |
| **L-c 评审清单** | agent / 人（L5 与 T2） | 判断类项：是否真有增量、结构与内容是否匹配、有无事实风险 | 是（T2 闸） |

#### L-b 机器门禁指标表（可直接实现为 CI 断言）

| 指标 | 阈值 | 检测方式 | 依据 |
|---|---|---|---|
| TL;DR 存在且为引用块 | 必须有，`>` 开头 | 正则 | 原始设计"必备要素" |
| TL;DR 句数 | ≤ 3 句 | 标点切分 | 原始 Gen 2 |
| 小标题数量 | ≤ 3 个 `###`（A/C 型可为 0） | 计数 | 原始决策指南"最多 3 个" |
| 段落长度 | ≤ 150 字（超出即拆） | 按空行切分 | **实测中位数最长段已达 152 字** |
| 最长句 | ≤ 60 字 | 句号切分 | **实测最长句中位数 68 字** |
| 标题长度 | 12–28 字，含「主体 + 动作 + 结果」 | 计数 + 评审 | SEO + 列表可读性 |
| 术语首现 | 英文缩略语首次出现须给中文释义 | 正则 | 中英夹杂是原始系统留有 `\n` 字面量的同类问题 |
| 脚注 | ≥ 3 条，编号连续不跳号，文末 `## 引用` | 解析 | 原始设计的严格版 |
| 套话 | 命中词表 ≤ 2 处 | 词表匹配 | 见下 |
| 占位符 | 无 `YYYY` / `{{ }}` / `TODO` | 正则 | 治存量 4,904 篇 |
| 配图 | `featured_image` 文件存在 | 文件系统 | 治存量 931 篇 |

**反套话词表（初始 15 个，可持续扩充）**：
`值得注意的是` `综上所述` `赋能` `闭环` `深度融合` `在当今` `随着人工智能的飞速发展` `不可忽视` `引发广泛关注` `具有里程碑意义` `开启了新篇章` `生态位` `抓手` `打法` `全方位`

### 3.4 三类文体各自的量化规范

| 文体 | 字数 | 结构 | 特有约束 |
|---|---|---|---|
| 洞察 | 800–1800 字 | 五型之一 + TL;DR + 脚注 | 事实必须能对应到源；禁止编造数字 |
| 早报 | 600–1000 字 | 导语（80–120 字）+ 编号列表（每条一句核心事实，粗体标题）+ 今日总结（≈80 字） | 每条必须带原文链接 |
| 日报 | 1500–2000 字 | 大标题 `AI内参日报 \| MM月DD日: <概括>` + 导语 100–150 字 + Top 5 模块（`### 标题` + 核心看点 2–3 句 + 内容摘要 ≈200 字 + 原文信息）+ 结尾总结 ≈100 字 | 继承原始 SRD `FR-06` |

### 3.5 提示词的组织方式

| 项 | 方案 | 理由 |
|---|---|---|

## 4. 提示词正文（可直接落盘使用）

### 4.1 `gate-relevance.md` —— 分类闸（S1）

```
你是一名中文科技媒体的选题编辑。判断下面这条资讯是否符合「AI内参」的收录标准。

## 收录标准（全部满足才通过）
1. 直接相关：涉及人工智能技术、算法、模型、应用、研究进展、行业趋势或公司动态。
2. 专业实质：有具体技术内容或行业影响，不是泛泛的社会话题。
3. 中文读者价值：能明确说出"这条对中文读者有什么用"（写不出即不通过）。
4. 垂直价值：AI 在医疗/金融/教育/工业等领域的实际应用或影响，算通过。

## 中国相关性（加分项，非必要条件）
涉及中国 AI 发展、政策、企业或研究成果的，优先通过。

## 排除项（命中任一即不通过）
- 社会、娱乐、政治、八卦等非专业性内容。
- 明显更吸引美国/欧洲读者的政治或社会争议，且对全球 AI 发展或中国无直接影响的。
- 纯产品促销、招聘、无技术或行业实质的融资快讯。
- 标题党、纯列表页、无信息量的转载。

## 输出
只输出 JSON，不要任何其他内容：
{"id": "<原样回填>", "pass": true|false, "reason": "<一句话理由，中文>"}

## 待判断条目
{{ items }}
```

### 4.2 `score.md` —— 多维打分（S2）

```
你是一名资深的 AI 行业分析师。请为下面每一条资讯的五个维度打分（1.0–10.0 的浮点数，保留一位小数）。

评分维度：
1. novelty   新颖性：是否包含突破性技术、新数据或新观点；还是复述已知信息。
2. impact    影响力：对行业（开发者/企业/监管/普通用户）的实际影响面与深度。
3. evidence  证据充分度：原文是否可及，是否含可核实的数字与一手表述（而非二手概述）。
4. readability 可读性：原文信息组织是否足以支撑一篇通俗易懂的改写。
5. freshness 时效性：相对当前时间的衰减程度。

评分要克制：大多数条目的分数应落在 4–8 之间。只有真正的突破性事件才给 9 以上。

只输出 JSON 数组，不要任何其他内容：
[{"id": "<原样回填>", "novelty": 0.0, "impact": 0.0, "evidence": 0.0,
  "readability": 0.0, "freshness": 0.0, "reason": "<一句话理由，中文>"}]

## 待评分条目
{{ items }}
```

> 注意：**不要**在这里让模型算总分。加权公式在代码里（`scoring.yaml`）。

### 4.3 `write-insight.md` —— 洞察写作（L2）

```
你是一名中文科技记者，写深度解释型科技报道。

## 风格
- 先讲清技术原理，再论行业与社会影响；两者都要，不能只转发事实。
- 语言准确但对非专家可读：术语首次出现时给出简明解释。
- 中立、不吹不黑，但要有前瞻判断——说清楚"这事为什么重要"。

## 结构（根据内容自己选，不要套模板）
A. 突发新闻型：开门见山陈述核心事实 → 按重要性递减展开 → 自然段落，不加小标题。
B. 深度分析型：最多 3 个小标题，如「技术原理」「行业影响」「下一步看什么」。
C. 人物/公司聚焦型：故事化叙述，按时间线或逻辑自然展开，避免生硬小标题。
D. 对比分析型：用对比段落或对比性小标题。
E. 教程/解释型：按理解难度递进，可用问题式小标题。

## 段落
- 每段只讲一个观点，超过 150 字必须拆段。
- 单句不超过 60 字。
- 关键数据与直接引语独立成段。

## 必备
- 开头 TL;DR：用 `>` 引用块，2–3 句话概括核心。
- 引用：正文用 `[^1]` `[^2]` 脚注，编号连续不跳号；文末 `## 引用` 逐条列出，
  格式 `[^1]: 作者（日期）。"[标题](URL)"。出版物。检索日期 <今天>`；
  无作者则以标题开头。

## 禁止
- 禁止编造数字、引语、事件细节；所有事实必须能在给定材料中找到。
- 禁止使用套话：值得注意的是 / 综上所述 / 赋能 / 闭环 / 深度融合 / 在当今 /
  随着人工智能的飞速发展 / 不可忽视 / 引发广泛关注 / 具有里程碑意义 / 开启新篇章。
- 不要输出 Markdown 代码块包裹；不要加文章大标题（标题是独立字段）。

## 输入
标题线索：{{ title }}
原文链接：{{ source_url }}
可用材料：
{{ source_material }}
```

### 4.4 `write-morning.md` / `write-daily.md` —— 早报与日报

早报（聚合，确定性轨为主）：

```
你是一名科技媒体早班编辑。把下面 N 条资讯编成一期「AI早报」。
要求：
1. 标题：`AI早报 YYYY年MM月DD日`
2. 导语：80–120 字，概括今日整体动向。
3. 正文：编号列表，每条一句话核心事实（粗体开头），必须带原文链接。
4. 结尾：【今日总结】约 80 字。
5. 语言精炼，不堆形容词，不使用套话。总字数 600–1000 字。
原文材料：{{ items }}
```

日报（综述）：

```
你是一位顶级科技媒体主编。把今天最重要的 5 条 AI 资讯整合成一篇「AI日报」。
要求：
1. 大标题：`AI内参日报 | MM月DD日: <当天最重要新闻的简短概括>`
2. 导语：100–150 字，概述今天 AI 领域最重要的动态与趋势。
3. 每条一个模块：`### 标题` + 核心看点（2–3 句）+ 内容摘要（约 200 字）+ 原文信息（作者 / 链接）。
4. 结尾总结：约 100 字。
5. 语言专业、流畅、精炼；总字数 1500–2000 字。
今日精选：{{ top5 }}
```

## 5. 现状实测基线（400 篇存量洞察抽样）

跑 `newsroom/_readability_audit.py` 得到（产物 `newsroom/_readability_out.json`）：

| 指标 | 实测 | 对照阈值 | 判断 |
|---|---|---|---|
| 有超 3 个 `###` 小标题 | **73.0%** | ≤3 个 | **系统性违规**——固定模板导致结构雷同 |
| 存在超 150 字段落 | **51.2%** | ≤150 字 | 段落偏长 |
| 最长段中位数 | **152 字** | ≤150 | 半数文章被单段拖垮 |
| 存在超 60 字长句 | **75.2%** | ≤60 字 | 长句是主要可读性瓶颈 |
| 最长句中位数 | **68 字** | ≤60 | 同上 |
| 无 TL;DR 引用块 | 17.0% | 必须有 | 需门禁 |
| TL;DR 超 3 句 | 13.8% | ≤3 句 | 需门禁 |
| 含套话 | 24.8%（全样本 155 处） | ≤2 处 | 需词表门禁 |
| 标题超 28 字 | 9.5% | 12–28 字 | 轻度 |
| 无脚注 | 4.5% | ≥3 条 | 尚可 |
| 正文字数中位数 | 1252 字 | 800–1800 | **合格** |
| 正文 < 400 字 | 0.5% | — | **合格** |

**结论：内容长度不是问题，粒度和结构是问题。** 具体就是三件事——段落太长、句子太长、小标题太多。这三条恰好都是**可以完全机器化检测**的，所以把它们放进 CI 门禁后，"可读性"第一次从审美变成了可执行的约束。

## 7. 需要你拍板

1. **时效窗定多少？** 原始是 4h（后期 0.5h）。我建议快讯 24h / 洞察 72h——因为中文 AI 资讯的搜索需求有长尾，4h 会把"48 小时前发布但今天才被搜索"的内容全部挡掉。
2. **θ1/θ2 初值**（T1 自动发 / T2 待审的门槛）用 6.5 / 7.5 起步可以吗？
3. **是否接受"不模仿在世记者"的改写**（§3.1）？如果你希望保留具体参照，我建议改为参照**机构风格**（如"MIT Technology Review 的深度报道体例"），而不是具体个人。
4. **配额是否接受**（早报 8–10 / 日报 1 期 / T1 ≤3 / T2 ≤2）？这是对"23 篇/天换 $0.36"的直接纠偏。
5. **`prompts/` 放公开仓库可以吗？**（我判断可以——它不是秘密，且版本化是它存在的意义；但公开后别人能直接复用你的选题标准，这是取舍。）
