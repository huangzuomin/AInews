你在前台摸鱼聊天，AI在后台把代码写完了：Claude Code这波更新有点逆天

温故智新AIGC实验室

TL;DR：

还在跟AI一问一答写代码？Claude Code直接给你整了个“分身”——你一边跟它唠嗑，一群子智能体已经在后台默默把代码重构、测试、PR全干完了。这都不是科幻片，是Anthropic创始人已经用了八个月的真实日常，连Spotify都用上了。

前几天，Claude Code的创造者Boris Cherny在X上扔了一颗“炸弹”：

下一版Claude Code，子智能体默认在后台跑。

一句话，让开发者群瞬间炸锅。翻译成人话就是：你可以在前台跟Claude聊架构、聊方案、甚至吐槽天气，而一群“AI打工人”已经在后台把活干完了。等你聊完天，低头一看——代码重构已提交，测试已通过，PR已开好。

这感觉，就像你还在琢磨晚饭吃啥，厨师已经把满汉全席端上了桌。

Boris本人更是凡尔赛到了极点：他已经八个月没手写过一行代码，有些日子同时管理着数千甚至上万个AI智能体。他原话说：“你不再是那个给Claude写提示的人了——写提示的是另一个Claude。”

好家伙，这是直接把自己从“写代码的”升级成“指挥AI写代码的”了。

从“一问一答”到“多线程工作流”

回看Claude Code这半年，这次更新并不是凭空冒出来的，而是一步步铺垫的水到渠成。

  • 4月，Routines上线：你可以把prompt+代码仓库打包成固定流程，按小时、按天触发，电脑合上盖子，智能体照样干活。cron回来了，但跑的不再是脚本，而是一群会读代码、改代码、开PR的AI工人。
  • 5月底，Dynamic workflows来了：对于大型迁移、全库审计这种一个对话框扛不住的任务，Claude会自己生成编排脚本，在后台调度几十到上百个子智能体分阶段推进，最后收束成一份报告。

而这次“后台子智能体默认运行”，就是把上面所有能力打包成开箱即用的默认行为：你不需要再说“去后台跑”，它天生就在后台跑。 你只需要专注于真正该做的事——思考下一步。

一个工程师翻三倍，但瓶颈变成了“决定写什么”

VentureBeat在6月27日发了一篇很劲爆的文章，标题就叫：Claude Code把每个工程师变成了三个，现在公司需要更多产品思考者。1

Anthropic最近告诉自己的增长团队：多招产品经理，不是多招工程师。原因简单粗暴——Claude Code已经把工程团队的产出拉到了实际人数的三倍。一个五人团队，现在干出十五到二十人的活。

瓶颈不在代码上了，瓶颈在“决定写什么代码”的人身上。

传统上，产品经理和工程师的配比大约是1:8。现在每个工程师产出翻三倍，配比在实际效果上变成了1:20。PM来不及给工程师派活了——工程师坐在那等需求，这画面想想就荒诞。

Spotify的实战：2000万行代码，AI卷起来了

最能说明“后台子智能体”有多猛的，是Spotify的实战数据。2

Spotify工程副总裁Niklas Gustavsson抖出了一组数字：每天生产环境部署约4500次，73%的拉取请求由AI辅助完成，PR频率直接提升75%以上。Niklas自己的日常是：同时开5到10个Claude会话，每个对应一个独立的git工作树，让多个智能体在后台并行干活，自己只负责看diff、做决策。

这一切发生在一个超过2000万行代码的超级单体仓库里。Niklas坦言原本担心代码库太大，智能体会迷路——结果出奇顺畅，Claude甚至能从仓库里其他代码中“找灵感”，知道该怎么写。

更有意思的是，Spotify把这套能力开放给了非工程师——产品经理、设计师，甚至联合CEO，都能用自然语言描述一个想法，Claude直接在真实代码里实现出原型。以前需要说服整个工程团队才能验证的想法，现在一两个小时就能跑通。

当“边聊边干活”成为默认设定

Niklas说，这事最早能追溯到五六年前——团队发现代码库增长速度比工程师数量快了七倍，逼着他们提前去想“机器能不能替人维护代码”。结果他发现，自己真正享受的从来不是敲代码本身，而是解决问题这件事。

现在他同时让好几个智能体在后台跑，腾出来的时间，用来想清楚下一步该做什么、和客户聊什么、做更多原型。

这恰好印证了Boris那条推文背后的判断：当后台子智能体成为标配，“写代码”不再是工程师最重要的事情，“决定干什么、判断对不对”才是。3

当“边聊边干活”从一个人的个人技巧，变成一家2900人工程团队的工作方式，AI编程工具就已经悄悄换了一个量级——工程师产出翻三倍，但最稀缺的不再是会写代码的人，而是知道该写什么代码的人。
