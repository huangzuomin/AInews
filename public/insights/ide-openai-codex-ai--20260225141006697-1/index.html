IDE 也要变“时代眼泪”？OpenAI Codex 负责人亲口承认：内部已很少再打开编辑器，代码全靠 AI “硬控”

温故智新AIGC实验室

TL;DR：

OpenAI 发布新一代旗舰编程模型 GPT-5.3-Codex，推理速度直接起飞。Codex 负责人 Alexander Embiricos 爆料：OpenAI 内部工程师现在已经很少打开 IDE 亲手敲代码了，基本都是“动动嘴”让 AI 自己干，人类则退居二线当起了“代码监工”。

如果有人告诉你，全球最顶尖的程序员现在已经不怎么用 IDE（集成开发环境）了，你可能会觉得他在开国际玩笑。毕竟，IDE 可是程序员的“命根子”，没了 VS Code 或 IntelliJ，代码难道靠意念传输？

然而，OpenAI Codex 的产品负责人 Alexander Embiricos 最近在一次深度访谈中亲口承认：在 OpenAI 内部，很多工程师几乎不再打开传统的代码编辑器。因为从 GPT-5.2 Codex 开始，大家的工作方式已经发生了“基因突变”：从“我跟 AI 一起写”，变成了“我直接把任务甩给 AI 跑”。12

GPT-5.3-Codex 驾到：这届智能体是来当“真同事”的

2 月初，OpenAI 正式祭出了最新大招——GPT-5.3-Codex。这不只是个简单的版本号升级，更是 OpenAI 想要把 AI 从“辅助插件”变成“全职协作者”的野心之作。3

在数据表现上，新版本在 SWE-Bench Pro 等硬核评测中直接霸榜，推理速度相比前代提升了约 25%。这意味着，当你还在纠结变量名怎么取时，它可能已经把整个系统的架构图画好并写完了。官方强调，这次升级的核心不在于“能写出更复杂的代码”，而在于它能像人类同事一样，深度参与到调试、审查甚至架构设计的每一个真实环节中。1

“现在开会期间如果没有让 Codex 同步处理任务，反而会被认为是在浪费时间。” Alexander 调侃道。

这种节奏感，大概就是所谓的“模型转一秒，人类少加一晚班”。

行业“地震”：分工在压缩，程序猿在“升职”？

Alexander 在访谈中抛出了一个相当炸裂的观点：未来五年，工程师的数量不但不会减少，反而会激增。 但代价是，你得重新定义什么是“工程师”。14

他提出了一个“人才栈压缩”的概念。以前一个项目组需要前端、后端、基建、产品经理各司其职，现在在 Codex 团队内部，这些界限已经模糊到看不见了。每个人都被要求具备“全栈能力”，甚至可以直接干掉产品经理（PM）的活儿。

在这种背景下，人类的角色正在发生转变：

  1. 从执行者变成定义者：你得知道问题在哪，并清晰地描述给 AI。
  2. 从敲代码变成做计划：GPT-5.3-Codex 新上线的“计划模式”（Plan Mode）要求 AI 先提交一份类似 RFC 的方案，征求人类的意见。
  3. 从搬砖工变成监工：真正的代码实现交给 AI，人类负责最后的一道“审美”和“质量把关”。15

这种转变就像是从手动挡换成了自动驾驶，你不需要亲自踩离合，但你得盯着路况，确保车别开进沟里。

Codex App：一个“没法写字”的编辑器

最有趣的一点是，OpenAI 最近发布的 Codex App 竟然刻意没有加入文本编辑功能。1

这在传统开发者看来简直是“反人类”的设计，但 Alexander 解释说，这是为了让用户强行切换到“委托模式”。如果你能随便改代码，你就会忍不住亲自上手去修那个小 Bug；而如果没有编辑框，你就会逼着自己去训练 AI 把活儿干得更漂亮。

调侃点评： 这就像是老板不给你笔，只给你一个能干活的秘书，逼着你学会怎么当一个“霸总”。

针对外界担心的“AI 垃圾代码（AI slop）”问题，OpenAI 的策略是“用 AI 治 AI”。现在 OpenAI 内部几乎所有的代码改动都会自动经过 Codex 的审查。如果 Codex 觉得这段代码写得不行，它会毫不留情地打回去——哪怕这段代码是它自己另一个模型生成的。1

未来预测：主动性才是唯一的“硬通货”

当被问及大学生该如何在 AI 时代生存时，Alexander 的建议异常简练：去构建高质量的东西。 1

在工具极其强大的今天，理解复杂系统的成本已经低到了地板上。当“构建”变得廉价，真正稀缺的是你对产品的审美、主动性和对质量的执念。如果你只会按部就班地当个“代码翻译机”，那可能真的要被这一波浪潮拍在沙滩上。

这场变革的核心瓶颈，其实不在算力，而在人类自己。正如 Alexander 所言，我们太习惯于手动操作，以至于缺乏足够的创意去发掘 AI 的所有潜力。未来的胜负手，或许就在于你能不能放下对 IDE 的依赖，去尝试定义一个更有趣的世界。
