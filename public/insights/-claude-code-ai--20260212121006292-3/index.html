每提一个 Claude Code 请求就点一根烟：这届程序员快被 AI “榨干”了？

TL;DR：

别再迷信“AI 让编程变轻松”的鬼话了！顶级工程师吐槽：AI 确实让单次任务快得飞起，但也把人变成了全天候待命的“电子保姆”。在这种效率悖论下，程序员正在经历一场前所未有的认知破产。

你以为有了 AI 辅助，程序员的生活就是喝着咖啡看模型自动写代码？醒醒吧，现实可能是：你正盯着屏幕上 Claude Code 疯狂跳动的字符，内心焦虑得想去阳台抽根烟。

最近，OpenFGA 核心维护者 Siddhant Khare 的一篇博文在技术圈炸了锅。1 这位深耕 AI Agent 基建的“硬核大佬”直言不讳：在 AI 时代，他比职业生涯任何阶段都要疲惫。那种感觉，就像是 AI 帮你移除了“自然限速器”，结果你自己成了那个最容易过热报废的零件。

效率悖论：任务变快了，人却“废”了

这件事最诡异的地方在于：AI 确实没撒谎，它真的变快了。以前要磨 3 小时的架构设计，现在 45 分钟就能整出一套像模像样的框架。但结果呢？你的工作量并没有减少，反而像被捅了马蜂窝一样成倍膨胀。2

“当每个任务变快，你不会做更少的任务，你只会做更多。”

这就是所谓的“产能黑洞”。老板看你交付快了，预期自然水涨船高；你自己看交付快了，也忍不住多接几个活儿。以前一天专注搞定一个大坑，虽然累，但有那种“深潜”的心流感。现在倒好，一天要在六个不同的 AI 生成任务里反复横跳。AI 不会累，但这种高频的上下文切换（Context Switching），简直是在人脑的内存条上疯狂蹦迪。

身份降级：从“造物主”变成“电子保姆”

很多程序员最初爱上编程，是因为那种“从无到有”创造世界的快感。但在 AI 时代，你的身份变了——你不再是那个亲手打磨零件的工匠，而是一个站在永不停歇的流水线旁，随时准备挑错的质检员。

这种“评审者”的工作，其实比“创造者”更消耗精力。3 面对 AI 吐出来的代码，你得像审犯人一样盯着：变量名对不对？逻辑有没有隐蔽的坑？是不是引入了莫名其妙的依赖？

“我并不觉得自己更高效了，反而感觉自己像个偷懒的保姆，只是勉强看着孩子别把自己弄伤而已。” —— 开发者 Parpfish 如此调侃。1

更扎心的是，AI 是非确定性的。同样的 prompt，周一给你写出优美的 API，周二可能就给你整出一堆乱码。这种“背景噪音式”的焦虑，让工程师最赖以生存的“确定性契约”彻底崩塌了。

FOMO 跑步机：追不上的技术，买不完的药

如果你觉得现在的 AI 工具多到看不过来，那不是错觉。Claude Code 刚发新技能，OpenAI 的 GPT-5.3-Codex 可能就在路上了，那边 Google 的 Gemini CLI 又在招手。1

这种“FOMO（错失恐惧症）跑步机”让大家陷入了疯狂的追新循环。为了追求那 5% 的效率提升，你可能花了一个周末去迁移工作流，结果下周三社交媒体上又吹起了新的风向标。

长期下来，最可怕的不是累，而是“思考肌肉”的萎缩。当遇到问题第一反应是问 AI，我们正在失去那种从零开始推理、在挣扎中学习的能力。1 就像习惯了 GPS 导航后，离开手机可能连家门口的菜市场都找不着。

幸存者指南：如何不被 AI 榨干？

面对这种“AI 疲劳”，大佬们给出了几条保命建议：

  1. 设立“时间盒”：提三次 Prompt 还没出结果？果断自己上手写，别在“Prompt 螺旋”里浪费生命。
  2. 接受“70% 原则”：别指望 AI 给你完美代码，把它当成一份有瑕疵的草稿，剩下的 30% 自己补齐，心理预期低了，幸福感就强了。
  3. 刻意练习“离线思考”：每天至少留一小时关掉 AI，用纸笔画图思考。保持大脑的“锋利度”，才是你在这个时代最硬的护城河。

说到底，AI 是工具，不是主子。正如 Siddhant Khare 所说，AI 时代最重要的技能不是 Prompt Engineering，而是知道什么时候该停下来。1 毕竟，你的大脑才是那个唯一的、不可替代的 CPU。
