DeepSeek V4.1-Flash 发布：KV 缓存降到 1/4，价格战进入“架构红利”深水区

温故智新AIGC实验室

TL;DR：

DeepSeek-V4.1-Flash 是全新 Causal Encoder-Decoder 架构家族的首个最小型号：552B MoE 主干，1M 上下文，原生视觉理解，全局 KV 缓存压到每 token 890 字节（约为 V4-Flash 的 1/4），API 价格同步下调。它的意义不在单项跑分，而在证明长上下文的成本曲线还可以靠架构再砍一刀。

架构账本：890 字节/token 意味着什么

根据 MarkTechPost 的拆解，V4.1-Flash 采用 552B 主干加 196B Engram 参数的 MoE 结构，prefill 阶段激活 8B 参数、decode 阶段激活 16B。真正的亮点在存储侧：全局 KV 缓存降至每 token 890 字节，约为上一代 V4-Flash 的 1/4；对 SSD 分层存储的需求也降到上一代的 1/8。官方评测给出的数字是 GPQA Diamond 90.9、HLE 36.8、Codeforces Rating 3471、Terminal-Bench 2.1 90.6。

对于长上下文场景，KV 缓存就是推理成本的地租。缓存需求降到 1/4，意味着同样显存可以服务约 4 倍的并发上下文，或者同样的负载用 1/4 的显存——这条账无论怎么算，都直接改写长文本智能体（代码仓库理解、长文档审阅、多轮 Agent 记忆）的单位经济性。

原生视觉 + 价格下调：智能体场景的实弹演习

这一代另一个关键变化是原生视觉理解被做进了基础模型，而不是外挂视觉编码器。对智能体工作流来说，屏幕截图、文档扫描件、UI 操作记录可以直接进入同一个上下文窗口，省掉了"视觉模型转译→文本模型推理"的中间损耗。

叠加同步宣布的 API 价格下调，DeepSeek 在编码与智能体场景打出的是"能力升级 + 成本下降"的组合拳。当部分竞品还在用融资补贴支撑低价时，DeepSeek 把降价做成了架构创新的副产品——前者烧的是钱，后者烧的是技术代差，后者的可持续性完全不同。

展望

值得注意的是 V4.1-Flash 定位为"新架构家族中最小的型号"。按照 DeepSeek 一贯的产品节奏，更大尺寸的同架构模型已在路上。如果 KV 压缩比能在更大模型上复现，长上下文推理的定价基准还会继续下探。
