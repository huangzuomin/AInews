Shopify 弃 React Native 迁回原生：AI 编码智能体改写的第一张技术选型多米诺

温故智新AIGC实验室

TL;DR：

跨平台框架存在的理由是"一套代码省两份钱"。Shopify 判断：LLM 编码智能体把"维护两套原生代码"的成本打到足够低，这笔账第一次算不平了——于是全面迁回 Swift 和 Kotlin。这不是一次普通的框架更换，而是 AI 第一次公开改写大型工程的基础选型假设。

迁移的经济学：被 AI 拆掉的立项前提

React Native 们的价值公式从来不是技术性的，而是财务性的：移动端双平台的重复开发成本太高，所以用一套 JS 代码换 70%-80% 的复用、接受性能与体验的折价。Shopify 在工程博客中给出的判断是，这个公式里"重复开发成本"这一项被 LLM 智能体大幅压缩——当智能体能高效产出并维护两套各自地道的原生代码时，跨平台框架省下的钱不再足以覆盖它引入的复杂度。假设变了，结论自然反转。

值得肯定的做法：把决策过程全部摊开

这次迁移的公开披露质量值得行业学习：迁移理由、自家开源库的去向、以及内部 Helix 工作流的处理方式都完整交代——对数千家依赖其开源 React Native 库的团队来说，这是负责任的退出姿态。大型工程的框架迁移失败率高，败因通常不是技术而是"只给结论不给路径"；Shopify 提供了一份可对照的施工图。

展望

这条新闻的辐射面超出移动开发本身：所有"为了省人力成本而做的技术折价"决策，都需要在 AI 编码时代重新算一遍。单体架构 vs 微服务、类型宽松 vs 严格、自建 vs 采购——凡是建立在"工程师时间昂贵"前提上的选型，前提都在松动。未来一年，预计会有更多公司跟进"迁回原生"或类似的重构；而跨平台阵营的应对，大概率是把自己的卖点从"省成本"转向"AI 工具链生态"。
